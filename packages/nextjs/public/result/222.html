BirdWatch Smart Contract — Security Audit Report

Job: leftclaw.services #222
Contract: BirdWatch.sol
Chain: Base (OP Stack, Canyon upgrade, 2-second blocks)
Token: $MYKCLAWD ERC-20 (0xE3C5FCfBfea42D5CE2492FD82c239B5503f17ba3)
Compiler: Solidity ^0.8.24
Audit Date: 2026-05-23
Methodologies: EthSkills (7 domain skills) + Pashov 8-Agent

Executive Summary

BirdWatch is a 1:1 over/under betting game on live bird feeder visits. An off-chain AI oracle sets the over/under threshold and submits the bird count; winners receive 2× their bet. The house funds the prize pool by depositing MYKCLAWD tokens directly into the contract.

The audit identified 2 High, 4 Medium, and 5 Low severity findings, plus 2 informational items. The most critical issues are:

  1. rescueFunds() can drain locked player bets — the NatSpec guarantee ("does not touch active bets") is completely unenforced by code. The owner can rug the contract at any time.
  2. Oracle can manipulate the threshold after all bets are placed — status remains OPEN between the betting deadline and activateRound(), giving the oracle a window to rewrite the line.
  3. No on-chain bird count validation — the oracle submits an unconstrained integer with zero verification. A compromised oracle can submit 0 to guarantee all OVER bets lose.
  4. No solvency enforcement — the contract neither checks house funding before accepting bets nor at resolution, causing first-come-first-served partial payouts when the house is underfunded.

Detailed Findings

[H-1] rescueFunds() drains locked player bet deposits

Severity: High | Confidence: 90 | Confirmed by: EthSkills + Pashov

Location: rescueFunds()

Description: The NatSpec comment states "Does NOT touch tokens locked as active bets (those are users' funds)", but the code provides zero enforcement of this invariant. Player bets (deposited via placeBet) and house liquidity share the same undifferentiated address(this) balance. rescueFunds performs an unconstrained safeTransfer of any requested amount with no accounting of outstanding bet liability:

function rescueFunds(address to, uint256 amount) external onlyOwner nonReentrant {
    if (to == address(0)) revert ZeroAddress();
    mykclawd.safeTransfer(to, amount);    // ← no bet-liability check
    emit FundsRescued(to, amount);
}

Exploit path:

  1. Owner pre-funds contract with 15 M MYKCLAWD as house liquidity.
  2. Three players each bet 5 M on OVER. Contract holds 30 M.
  3. Round enters ACTIVE.
  4. Owner calls rescueFunds(owner, 30_000_000e18). All 30 M transferred out.
  5. Oracle resolves — OVER wins. Three players call claim().
  6. Every claim() reverts InsufficientHouseFunds. Players' 15 M in bets is permanently gone.

Recommendation: Track bet liability explicitly and enforce it in rescueFunds:

uint256 public totalActiveBets;

// In placeBet():
mykclawd.safeTransferFrom(msg.sender, address(this), amount);
totalActiveBets += amount;

// In claim() — win and loss branches:
totalActiveBets -= b.amount;

// In cancelRound() refund loop:
totalActiveBets -= b.amount;

function rescueFunds(address to, uint256 amount) external onlyOwner nonReentrant {
    if (to == address(0)) revert ZeroAddress();
    uint256 rescuable = mykclawd.balanceOf(address(this)) - totalActiveBets;
    if (amount > rescuable) revert InsufficientHouseFunds();
    mykclawd.safeTransfer(to, amount);
    emit FundsRescued(to, amount);
}

[H-2] Centralized oracle controls both betting line and bird count with no on-chain validation

Severity: High | Confidence: 90 | Confirmed by: EthSkills + Pashov

Location: setThreshold(), resolveRound()

Description: A single EOA oracle has unilateral, uncheckable control over the two parameters that determine every round's outcome:

  1. thresholdScaled — the betting line, settable (and re-settable) by oracle at any time while OPEN.
  2. birdCount — the resolution value, submitted verbatim with zero on-chain verification:
function resolveRound(uint256 roundId, uint256 birdCount) external onlyOracle {
    ...
    r.birdCount = birdCount;       // ← accepted as truth, no bounds or sanity check
    r.status = RoundStatus.RESOLVED;
    bool overWins = birdCount * 100 > r.thresholdScaled;
    ...
}

A compromised or malicious oracle can submit birdCount = 0 after all OVER bets are visible on-chain, causing 100% of OVER bettors to lose their principal with no on-chain evidence of manipulation.

Exploit path:

  1. Players bet OVER expecting normal bird activity.
  2. Betting window closes. Oracle calls resolveRound(id, 0).
  3. 0 * 100 > threshold → false → UNDER wins.
  4. All OVER bettors lose principal. UNDER bettors (or house) collect 2×.

Recommendation (no fully trustless fix possible with current design):

  • Prohibit threshold changes once the first bet is placed (see M-1).
  • Add a dispute window before claims open.
  • Require 2-of-2 multi-sig for resolveRound and setOracle.
  • Document clearly that the oracle is a fully trusted operator key.

[M-1] setThreshold() callable after betting window closes — oracle can rewrite committed line

Severity: Medium | Confidence: 90 | Confirmed by: EthSkills + Pashov

Location: setThreshold()

Description: setThreshold checks only r.status == RoundStatus.OPEN. A round remains OPEN until activateRound() is called, which requires block.timestamp >= r.bettingEndsAt. Between the betting deadline expiring and activateRound() being called, the oracle can change the threshold — while no new bets are possible, all existing bets are already committed.

Additionally, setThreshold can be called multiple times during the active betting window, allowing the oracle to observe accumulating bet distribution and adjust the line.

function setThreshold(uint256 roundId, uint256 thresholdScaled) external onlyOracle {
    Round storage r = _rounds[roundId];
    if (r.status != RoundStatus.OPEN) revert WrongStatus();  // ← OPEN persists past bettingEndsAt
    r.thresholdScaled = thresholdScaled;

Exploit path:

  1. Oracle sets threshold at 300 (3.00 birds). Players bet OVER.
  2. Betting window closes. No one calls activateRound() immediately.
  3. Oracle calls setThreshold(id, 5000) (50.00 birds — unachievable).
  4. Oracle calls resolveRound(id, 10). UNDER wins. All OVER bettors lose.

Recommendation:

function setThreshold(uint256 roundId, uint256 thresholdScaled) external onlyOracle {
    Round storage r = _rounds[roundId];
    if (r.status != RoundStatus.OPEN) revert WrongStatus();
    if (block.timestamp >= r.bettingEndsAt) revert BettingClosed();   // ← freeze post-deadline
    if (r.thresholdScaled != 0) revert ThresholdAlreadySet();         // ← immutable once set
    if (thresholdScaled == 0) revert InvalidThreshold();
    r.thresholdScaled = thresholdScaled;
    emit ThresholdSet(roundId, thresholdScaled);
}

[M-2] No house solvency enforcement — underfunding causes first-come-first-served partial payout

Severity: Medium | Confidence: 85 | Confirmed by: EthSkills + Pashov

Location: placeBet(), claim()

Description: The contract never checks that the house has sufficient reserves before accepting bets, and only checks per-claim at transfer time:

uint256 balance = mykclawd.balanceOf(address(this));
if (balance < payout) revert InsufficientHouseFunds();

If the house is underfunded, first claimants succeed while later claimants are permanently denied their winnings — even though their bet principal was already forfeited to the contract.

Exploit path:

  • 3 OVER bettors each stake 5 M. OVER wins. House deposited only 5 M.
  • Contract holds 20 M. First two winners claim 10 M each (20 M → 0 M).
  • Third winner: 0 < 10M → InsufficientHouseFunds — permanently blocked unless house adds funds.

Recommendation: Validate solvency at resolveRound(), after the winning side is known:

function resolveRound(uint256 roundId, uint256 birdCount) external onlyOracle {
    ...
    bool overWins = birdCount * 100 > r.thresholdScaled;
    uint256 maxPayout = 0;
    for (uint256 i = 0; i < r.betCount; i++) {
        Bet storage b = r.bets[i];
        if ((overWins && b.choice == BetChoice.OVER) || (!overWins && b.choice == BetChoice.UNDER)) {
            maxPayout += b.amount * 2;
        }
    }
    if (mykclawd.balanceOf(address(this)) < maxPayout) revert InsufficientHouseFunds();
    r.birdCount = birdCount;
    r.status = RoundStatus.RESOLVED;
    ...
}

[M-3] maxLiabilityCurrentRound() understates true exposure by up to 2×

Severity: Medium | Confidence: 80 | Confirmed by: EthSkills + Pashov

Location: maxLiabilityCurrentRound()

Description: The function sums bet principals, not payouts:

for (uint256 i = 0; i < r.betCount; i++) {
    liability += r.bets[i].amount;   // ← 1× per bet; actual payout is 2×
}

If all players bet the same side and win, each is owed 2× their bet. A house operator using this function for funding decisions will under-fund by exactly the total bet pool. The function also ignores unclaimed payouts from previously resolved rounds.

Recommendation:

/// @notice Maximum payout the contract must be able to fulfill across ALL unresolved rounds.
/// @dev With lockedBets tracking (recommended), this is simply: return lockedBets;
function maxPayoutCurrentRound() external view returns (uint256 maxPayout) {
    if (currentRoundId == 0) return 0;
    Round storage r = _rounds[currentRoundId];
    for (uint256 i = 0; i < r.betCount; i++) {
        maxPayout += r.bets[i].amount * 2;
    }
}

[M-4] Owner can observe off-chain outcome and cancel a winning round before on-chain resolution

Severity: Medium | Confidence: 90 | Confirmed by: EthSkills

Location: cancelRound()

Description: cancelRound() accepts OPEN and ACTIVE rounds with no time constraint. Since the real bird count is known off-chain (to the same operators running the system) before resolveRound() is called, the owner can selectively cancel rounds where OVER would win:

function cancelRound(uint256 roundId) external onlyOwner nonReentrant {
    Round storage r = _rounds[roundId];
    if (r.status != RoundStatus.OPEN && r.status != RoundStatus.ACTIVE) revert WrongStatus();
    r.status = RoundStatus.CANCELLED;
    ...
    mykclawd.safeTransfer(b.player, b.amount);   // refund only — no 2× payout

Winners are refunded their principal only, denied their 2× winning payout.

Recommendation: Prevent cancellation after the round has ended when bets exist:

function cancelRound(uint256 roundId) external onlyOwner nonReentrant {
    Round storage r = _rounds[roundId];
    if (r.status != RoundStatus.OPEN && r.status != RoundStatus.ACTIVE) revert WrongStatus();
    if (block.timestamp >= r.roundEndsAt && r.betCount > 0) revert RoundAlreadyEnded();
    ...
}

[L-1] setThreshold() accepts zero, bricking round resolution

Severity: Low | Confidence: 75 | Confirmed by: EthSkills + Pashov

Location: setThreshold()

Description: If the oracle calls setThreshold(roundId, 0) after bets are placed, both resolveRound() and future placeBet() calls revert with ThresholdNotSet. The round is permanently stuck until the owner manually calls cancelRound().

Recommendation: if (thresholdScaled == 0) revert InvalidThreshold(); at top of setThreshold(). (Superseded entirely by the M-1 fix which makes the threshold immutable once set.)

[L-2] Permissionless startRound() enables orphaned unserviced rounds

Severity: Low | Confidence: 75 | Confirmed by: EthSkills + Pashov

Location: startRound()

Description: Any EOA can call startRound(), creating a round the oracle may not service. If a bettor places a bet into such a round, their funds are locked until the owner calls cancelRound(). While funds are ultimately recoverable, this creates forced dependency on owner responsiveness.

Recommendation: Restrict to onlyOwner or onlyOracle.

[L-3] Exact-threshold tie silently resolves as UNDER win

Severity: Low | Confidence: 70 | Confirmed by: EthSkills + Pashov

Location: resolveRound(), claim()

Description: bool overWins = birdCount * 100 > r.thresholdScaled is a strict greater-than. If thresholdScaled = 300 and birdCount = 3, the result is 300 > 300 = false — UNDER wins. This counterintuitive behavior is undocumented in NatSpec. The NatSpec recommends fractional lines but does not enforce them.

Recommendation: Enforce fractional thresholds: if (thresholdScaled % 100 == 0) revert ThresholdMustBeFractional();

[L-4] 30-second betting/counting windows are impractically short and sequencer-manipulable

Severity: Low | Confirmed by: EthSkills

Location: BETTING_WINDOW, ROUND_DURATION constants

Description: Both windows are 30 seconds on Base (15 L2 blocks). The Base sequencer can skew block.timestamp by ~12 seconds — a 40% distortion of the betting window. Users need time to pre-approve tokens and submit a bet transaction; 30 seconds is insufficient for most users outside of pre-configured bots.

Recommendation: Increase both constants: BETTING_WINDOW = 300 (5 minutes), ROUND_DURATION = 300 (5 minutes).

[L-5] No event emitted for losing claim() calls

Severity: Low | Confirmed by: EthSkills + Pashov

Location: claim()

Description: When a losing player calls claim(), b.claimed is set to true but no event is emitted. Off-chain indexers will never detect this state change, causing losing bets to appear perpetually unclaimed in the event log and UI.

Recommendation: emit LossClaimed(roundId, msg.sender); in the non-winning branch.

[I-1] setOracle() takes effect immediately, enabling mid-round oracle substitution

Severity: Info | Confirmed by: Pashov

Location: setOracle()

Description: The owner can replace the oracle address mid-round with no status guard, immediately authorizing a new address to call resolveRound() on the active round. Combined with H-2, this means a single owner action can redirect an in-flight round to any oracle.

Recommendation: Add if (round is OPEN or ACTIVE) revert RoundInProgress() to setOracle().

[I-2] setMaxPlayersPerRound() applies immediately to in-progress rounds

Severity: Info | Confirmed by: EthSkills

Location: setMaxPlayersPerRound()

Description: If reduced mid-round below r.betCount, the round effectively becomes permanently full. Users who expected to be able to bet find the round closed.

Recommended Fix Priority

  1. Immediate (before mainnet): H-1 — add totalActiveBets tracking and enforce it in rescueFunds.
  2. Immediate (before mainnet): M-1 — freeze threshold once betting window opens and make it immutable once set.
  3. Before mainnet: M-2 — add solvency check at resolveRound().
  4. Before mainnet: M-4 — prevent post-roundEndsAt cancellation when bets exist.
  5. Before mainnet: I-1 — guard setOracle() during active rounds.
  6. Strongly recommended: Increase BETTING_WINDOW and ROUND_DURATION to ≥ 300 seconds.
  7. Recommended: Rename maxLiabilityCurrentRound() or fix its arithmetic.
  8. Recommended: Enforce fractional thresholds (thresholdScaled % 100 != 0).
  9. Recommended: Add LossClaimed event.
  10. Operational: Document the full oracle trust model prominently in the UI.
