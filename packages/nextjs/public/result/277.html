Findings

[90] 1. Borrower USDC-Blacklist Forces Default — Permanent Repayment DoS

PMFIPositionVaultV22.repayInFull · Confidence: 90

Description
repayInFull() pulls USDC directly from borrower via _safeTransferRepaymentUsdcFromExact(borrower, required) and hard-checks that msg.sender == borrower; if Circle's blocklist is applied to the borrower address at any point after funding closes, the transfer reverts on every call, the repayment deadline passes, and default settlement fires — transferring all collateral to P holders instead of USDC repayment.

Fix

- _safeTransferRepaymentUsdcFromExact(borrower, required);
+ _safeTransferRepaymentUsdcFromExact(msg.sender, required);

With msg.sender == borrower already enforced above, the behavior is identical for the normal path; but a proxy/agent contract that the borrower controls and is not blocklisted could satisfy the payment.

[80] 2. Inline USDC Push to Seller Permanently DoS's All Buys If Seller Is Blocklisted

PMFIPrimaryMarketplaceV22.buy · Confidence: 80

Description
buy() forwards sellerPrice USDC directly to s.seller (the borrower) inline before P tokens are delivered and before closeFunding is called; if the seller's address is on USDC's blocklist (applied by Circle at any time after position creation), every call to buy() reverts, permanently blocking primary-market purchases for that vault for the remainder of the funding window and forcing eventual closeExpired with no funding.

Fix

- _safeTransferUsdcExact(s.seller, sellerPrice);
+ pendingProceeds[s.seller] += sellerPrice;

Replace the push with a pull-payment mapping; add a withdrawProceeds() function so the seller claims accumulated USDC independently of buyer transactions.

[75] 3. _redeemP Burns P Tokens for Zero Output When USDC Pool Is Tiny Relative to Supply

PMFIPositionVaultV22._redeemP · Confidence: 75 · [agents: 1, 3, 6, 12]

Description
previewRedeemP uses Math.mulDiv(usdcPoolRemaining, amount, P.totalSupply()) with floor division; in early (USDC) settlement with high-decimal collateral (e.g., 18-decimal ETH-like token with 1e18 supply) and a USDC target that is orders of magnitude smaller, usdcOut rounds to zero for any redemption below ceil(P.totalSupply() / usdcPaid) tokens — and _redeemP burns the caller's P tokens and transfers nothing, silently destroying the position.

[75] 4. Implicit Minimum Purchase Lot: quoteUsdc Returns Zero for Small Buys When usdcTotal ≪ amountInitial

PMFIPrimaryMarketplaceV22.buy / quoteUsdc · Confidence: 75 · [agent: 10]

Description
quoteUsdc computes Math.mulDiv(s.usdcTotal, amountSoldAfter, s.amountInitial); when s.usdcTotal (USDC 6-decimal) is far smaller than s.amountInitial (collateral in native decimals, up to 30), any pAmount below ceil(amountInitial / usdcTotal) produces sellerPrice = 0 and the ZeroUsdcCost revert fires; in the extreme case (amountInitial = 1e30, usdcTotal = 1), the sale is purchasable only in one atomic all-or-nothing transaction since no partial fill can yield non-zero price.
