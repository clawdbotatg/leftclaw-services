Contract Overview

PawthereumMamoYieldModule is a Gnosis Safe module deployed on Base (OP Stack, chain 8453). It manages yield capture from a three-bucket DeFi strategy (MetaMorpho ERC-4626 vault + Moonwell Compound-fork mToken + idle USDC) and distributes yield above a protected watermark to a list of recipients.

Key design choices relevant to security:

  • Permissionless execution: executeYieldCapture() is callable by anyone after executionInterval has elapsed.
  • Push-payment model: recipients receive USDC via Safe module calls inside a loop.
  • Immutable addresses: SAFE, MAMO_STRATEGY, USDC, M_TOKEN, META_MORPHO_VAULT are set at construction and never change.
  • Dual-measurement invariant: strategy value is read before the withdrawal (to compute yield) and again after (to verify the principal watermark is intact). This design is the root cause of two of the three medium-severity findings.

Findings confirmed by both audit passes receive a confidence boost.

Findings

[H-1] Single Blocked USDC Recipient Permanently Halts All Yield Distribution

Severity: High
Confirmed by: EthSkills (M-1) + Pashov (#1 at confidence 95)
Location: _payRecipients() — lines 211–221

Description

_payRecipients iterates over every configured recipient and executes a USDC transfer through the Safe module interface for each one:

// Lines 216-218
address to = _recipients[i].addr;
_safeExec(USDC, abi.encodeCall(IERC20Minimal.transfer, (to, amt)));
emit YieldDistributed(to, amt);

USDC on Base is a Centre/Circle-issued token with an on-chain blocklist. If any recipient is blocklisted, USDC.transfer reverts. _safeExec propagates this as SafeCallFailed, which unwinds the entire executeYieldCapture transaction. Because _payRecipients has no per-recipient error handling and lastExecutionTimestamp is only updated on success, every subsequent call to executeYieldCapture will fail identically until the Safe calls setRecipients to remove the blocked address.

Proof of Concept

  1. Safe configures recipients: [charityAddr (5000 bps), teamAddr (3000 bps)].
  2. Circle places charityAddr on the USDC blocklist.
  3. Keeper calls executeYieldCapture(). totalDistributed = 800 USDC. Strategy withdrawal succeeds and 800 USDC lands in the Safe.
  4. _payRecipients pays teamAddr (300 USDC) — succeeds.
  5. _payRecipients attempts charityAddr (500 USDC) → USDC reverts → SafeCallFailed → entire transaction reverts, including the 300 USDC payment to teamAddr.
  6. All future executeYieldCapture calls fail at the same step. No recipient receives any yield.

Recommendation

Replace the all-or-nothing payment loop with partial-failure tolerance. Two options:

Option A — Skip-on-failure: capture failed payments in an unclaimedYield mapping; re-route undelivered amounts into compoundedAmount:

function _payRecipients(uint256[] memory amounts) internal returns (uint256 actualDistributed) {
    for (uint256 i; i < amounts.length; ++i) {
        uint256 amt = amounts[i];
        if (amt == 0) continue;
        address to = _recipients[i].addr;
        (bool ok, bytes memory ret) = ISafe(SAFE).execTransactionFromModuleReturnData(
            USDC, 0, abi.encodeCall(IERC20Minimal.transfer, (to, amt)), ISafe.Operation.Call
        );
        bool transferred = ok && (ret.length == 0 || abi.decode(ret, (bool)));
        if (transferred) {
            actualDistributed += amt;
            emit YieldDistributed(to, amt);
        } else {
            emit TransferSkipped(to, amt);
        }
    }
}

Option B — Pull-payment: record claimable balances in a mapping; let recipients call a claim() function. This is the canonical ERC-20 DoS-resistant pattern and eliminates the entire class of push-payment failures.

[M-1] ERC-4626 Share Rounding After Withdrawal Triggers Permanent PrincipalViolation DoS

Severity: Medium
Confirmed by: EthSkills (M-2) + Pashov (#2 at confidence 92)
Location: executeYieldCapture() — line 177

Description

After distributing yield, executeYieldCapture updates protectedPrincipal and then re-reads the strategy value to verify the invariant:

// Lines 176-177
protectedPrincipal += compoundedAmount;
if (getStrategyValue() + getSafeUSDC() < protectedPrincipal) revert PrincipalViolation();

The new protectedPrincipal equals strategyValueBefore + safeIdleBefore - totalDistributed (algebraically). After the withdrawal, the remaining MetaMorpho shares are worth strategyValueBefore - totalDistributed - ε where ε ≥ 1 wei due to ERC-4626's mandated round-down semantics in convertToAssets. The invariant check then evaluates:

post-value  = (strategyValueBefore - totalDistributed - ε) + safeIdleBefore
newPrincipal = strategyValueBefore + safeIdleBefore - totalDistributed

Since post-value < newPrincipal whenever ε ≥ 1, the check always reverts after any non-trivial MetaMorpho redemption. The function becomes permanently uncallable until the Safe manually reduces protectedPrincipal via setProtectedPrincipal.

Proof of Concept

  1. protectedPrincipal = 1,000,000 USDC. Strategy value = 1,001,000 USDC. totalYield = 1,000 USDC.
  2. totalDistributed = 1,000 USDC. compoundedAmount = 0.
  3. Strategy redeems MetaMorpho shares to deliver exactly 1,000 USDC. Due to ERC-4626 rounding, remaining shares convert to 999,999 USDC (1 wei short).
  4. newProtectedPrincipal = 1,000,000 USDC.
  5. Post-check: 999,999 + safeIdleBefore < 1,000,000 + safeIdleBefore → PrincipalViolation reverts.

Recommendation

Add a small rounding tolerance to the invariant check:

-if (getStrategyValue() + getSafeUSDC() < protectedPrincipal) revert PrincipalViolation();
+uint256 ROUNDING_TOLERANCE = 2; // 2 wei covers 1-wei precision loss in both MetaMorpho and Moonwell
+if (getStrategyValue() + getSafeUSDC() + ROUNDING_TOLERANCE < protectedPrincipal) revert PrincipalViolation();

Alternatively, compute protectedPrincipal using a snapshot of the pre-withdrawal strategy value minus the actual amount delivered (measured via balance difference rather than re-calling getStrategyValue()), avoiding the post-withdrawal re-read entirely.

[M-2] Strategy Withdrawal Rounding Can Trigger WithdrawFailed DoS

Severity: Medium
Confirmed by: EthSkills (M-3) + Pashov (#10 at confidence 73, different scenario)
Location: executeYieldCapture() — lines 170–172

Description

getStrategyValue() uses convertToAssets(morphoShares) to estimate the MetaMorpho position's USDC value. This estimate is rounded down per ERC-4626. totalDistributed is derived from this rounded-down estimate. When IMamoStrategy.withdraw(totalDistributed) is called, the strategy must actually redeem shares and deliver exactly totalDistributed USDC. If MetaMorpho or Moonwell rounds during actual redemption (against the redeemer), the strategy may only deliver totalDistributed - δ, causing the delivery check to fail:

// Line 171
if (getSafeUSDC() < safeIdleBefore + totalDistributed) revert WithdrawFailed();

Unlike M-1 (which fails post-payment), this fails before any recipients are paid, with no state changes committed.

Proof of Concept

  1. Strategy holds 1,001,000 USDC entirely in MetaMorpho. totalDistributed = 1,000 USDC.
  2. MetaMorpho true share price: 1,001,000.0000005 USDC (sub-unit precision).
  3. convertToAssets returns 1,001,000 USDC (rounds down).
  4. IMamoStrategy.withdraw(1_000_000_000) redeems shares. MetaMorpho delivers 999,999,999 units (rounds down during actual redeem).
  5. getSafeUSDC() = safeIdleBefore + 999_999_999 < safeIdleBefore + 1_000_000_000 → WithdrawFailed.

Recommendation

Reduce the requested withdrawal by a 1-unit buffer, or switch to a "withdraw at least" interface where IMamoStrategy.withdraw returns the actual delivered amount:

-_safeExec(MAMO_STRATEGY, abi.encodeCall(IMamoStrategy.withdraw, (totalDistributed)));
-if (getSafeUSDC() < safeIdleBefore + totalDistributed) revert WithdrawFailed();
+uint256 requestAmount = totalDistributed > 0 ? totalDistributed - 1 : 0;
+_safeExec(MAMO_STRATEGY, abi.encodeCall(IMamoStrategy.withdraw, (requestAmount)));
+if (getSafeUSDC() < safeIdleBefore + requestAmount) revert WithdrawFailed();

A cleaner long-term fix is to measure actual USDC received via getSafeUSDC() - safeIdleBefore after the withdrawal and use that as the basis for recipient payments.

[M-3] _safeExec Silently Accepts Zero-Length Return Data for USDC Transfers

Severity: Medium (downgraded from pashov High; low probability, requires future change)
Confirmed by: Pashov (#4 at confidence 87)
Location: _safeExec() — lines 277–282

Description

if (ret.length != 0 && !abi.decode(ret, (bool))) revert SafeCallFailed();

The ret.length != 0 short-circuit means zero-length returndata is treated as success. For current Base USDC (which always returns bool true on successful transfer), this works correctly. However:

  1. Non-contract target: If the USDC immutable is misconfigured to point to an EOA or undeployed address, the EVM returns (ok=true, ret=""). The module considers all transfers successful while no tokens move.
  2. Future USDC upgrade: USDC is an upgradeable proxy. A future version that changes return encoding could produce empty returndata on success — or on failure, silently bypassing the check.
  3. Different behavior for withdraw vs transfer calls: The _safeExec function is used for both the IMamoStrategy.withdraw call (void return — empty returndata is correct) and USDC transfer calls (bool return — empty returndata is not a valid success indicator).

Recommendation

Split _safeExec into two helpers: one for void-return calls (_safeExecVoid) and one for ERC-20 transfers that requires explicit true return:

-function _safeExec(address to, bytes memory data) internal {
-    (bool ok, bytes memory ret) = ...
-    if (!ok) revert SafeCallFailed();
-    if (ret.length != 0 && !abi.decode(ret, (bool))) revert SafeCallFailed();
-}
+function _safeExecToken(address to, bytes memory data) internal {
+    (bool ok, bytes memory ret) = ISafe(SAFE).execTransactionFromModuleReturnData(to, 0, data, ISafe.Operation.Call);
+    if (!ok) revert SafeCallFailed();
+    if (ret.length == 0 || !abi.decode(ret, (bool))) revert SafeCallFailed(); // require explicit true
+}
+function _safeExecVoid(address to, bytes memory data) internal {
+    (bool ok,) = ISafe(SAFE).execTransactionFromModuleReturnData(to, 0, data, ISafe.Operation.Call);
+    if (!ok) revert SafeCallFailed();
+}

Use _safeExecToken for USDC.transfer calls and _safeExecVoid for MAMO_STRATEGY.withdraw.

[L-1] getStrategyValue() and previewYieldCapture() Are State-Mutating

Severity: Low
Confirmed by: EthSkills (L-1) + Pashov (#3 at confidence 88)
Location: getStrategyValue() — line 110; previewYieldCapture() — line 184

Description

getStrategyValue() calls IMToken(M_TOKEN).balanceOfUnderlying(MAMO_STRATEGY), which is a non-view function that triggers Moonwell's accrueInterest() as a side effect. This writes updated borrow indexes and accrual timestamps to Moonwell's storage on every call.

Consequently, previewYieldCapture() — named and designed as a read-only simulation — actually modifies Moonwell chain state. Any on-chain contract that calls previewYieldCapture() via staticcall (the standard for view queries) will receive a revert. Off-chain eth_call queries work but silently trigger state mutations on archive nodes.

Recommendation

Document the state-mutating behavior prominently in NatSpec. Where possible, provide a view-compatible alternative using exchangeRateStored() (the cached, non-accruing Moonwell balance) for the preview path:

/// @notice Non-view: triggers Moonwell interest accrual. Do not call via staticcall.
function getStrategyValue() public returns (uint256) { ... }

/// @notice View-safe approximation; uses stored exchange rate without accrual.
function getStrategyValueView() public view returns (uint256) {
    // Use balanceOf + exchangeRateStored instead of balanceOfUnderlying
    ...
}

[L-2] Constructor Does Not Validate SAFE != MAMO_STRATEGY

Severity: Low
Confirmed by: EthSkills (L-2) + Pashov (#9 at confidence 75)
Location: constructor — lines 89–108

Description

The constructor validates non-zero addresses but does not verify that safe_ and mamoStrategy_ are distinct. If set to the same address by deployment error, getStrategyValue() and getSafeUSDC() would both read USDC.balanceOf(same_address), double-counting the USDC balance in the total value calculation. This inflates totalYield and causes the module to attempt to distribute funds that do not exist as true yield.

Since all relevant addresses are immutable, a misconfigured deployment cannot be corrected after deployment.

Recommendation

+if (safe_ == mamoStrategy_) revert ZeroAddress();

[L-3] setProtectedPrincipal Has No Lower Bound — Enables Instant Drainage If Safe Is Compromised

Severity: Low
Confirmed by: Pashov (#6 at confidence 82)
Location: setProtectedPrincipal() — lines 227–229

Description

The Safe multisig can set protectedPrincipal to any value including zero without any floor validation or time-lock. If the Safe multisig is compromised (key theft, social engineering, malicious proposal), an attacker who controls sufficient signers can:

  1. Call setRecipients to route all BPS to an attacker-controlled address.
  2. Call setProtectedPrincipal(0).
  3. Call executeYieldCapture() — the entire strategy value + Safe USDC is treated as yield and drained to the attacker.

This is by design (the Safe is the administrator), but there is no rate-limiting or time-delay that would give users a window to react.

Recommendation

Implement a minimum time-lock on setProtectedPrincipal and setRecipients changes (e.g., 24–48 hours), giving parties that monitor the module an opportunity to detect and respond to malicious proposals before execution.

[L-4] External Dependency Risk: USDC Global Pause / Moonwell Market Outage

Severity: Low
Confirmed by: EthSkills (L-3)
Location: _payRecipients() — line 217; getStrategyValue() — line 113

Description

The module has two unmitigated external dependency failure modes:

  1. USDC global pause: Circle can pause all USDC transfers on Base. If paused, all _payRecipients calls fail, blocking yield distribution indefinitely. Unlike M-1 (single blocked recipient), a global pause cannot be remedied by updating recipients.

  2. Moonwell market pause: Moonwell's guardian multisig can pause markets. If the mToken market is paused, balanceOfUnderlying may revert, causing getStrategyValue() to revert and blocking all module operations.

Neither failure mode has a try/catch fallback or emergency escape path.

Recommendation

Wrap the Moonwell call in try/catch with a configurable fallback to a cached value:

try IMToken(M_TOKEN).balanceOfUnderlying(MAMO_STRATEGY) returns (uint256 val) {
    moonwellAssets = val;
} catch {
    moonwellAssets = 0; // conservative fallback
}

For the USDC pause risk, document it as an unmitigated external dependency and consider adding a Safe-callable emergency pause mechanism that the Safe can use preemptively if Circle signals an impending pause.

[I-1] Constructor Does Not Emit Initial Parameter Events

Severity: Info
Confirmed by: EthSkills (I-1)
Location: constructor — lines 103–107

Description

The constructor sets protectedPrincipal, executionInterval, and minimumClaimAmount without emitting the ProtectedPrincipalUpdated, ExecutionIntervalUpdated, and MinimumClaimAmountUpdated events. Off-chain indexers reconstructing state from event logs cannot observe initial values.

Recommendation

emit ProtectedPrincipalUpdated(0, protectedPrincipal_);
emit ExecutionIntervalUpdated(0, executionInterval_);
emit MinimumClaimAmountUpdated(0, minimumClaimAmount_);

[I-2] All-Compound Mode Requires minimumClaimAmount == 0 — Not Enforced or Documented

Severity: Info
Confirmed by: EthSkills (I-2) + Pashov (#7)
Location: setRecipients() — line 223; executeYieldCapture() — lines 166–167

Description

When the Safe removes all recipients (setRecipients([])), _computeAmounts always returns totalDistributed = 0. The check if (totalDistributed < minimumClaimAmount) revert BelowMinimum() will then revert every call to executeYieldCapture unless minimumClaimAmount is also set to zero. This coupling is not enforced or documented.

Recommendation

Auto-zero minimumClaimAmount when entering all-compound mode, or skip the minimum check when there are no recipients:

+if (newRecipients.length == 0 && minimumClaimAmount > 0) {
+    emit MinimumClaimAmountUpdated(minimumClaimAmount, 0);
+    minimumClaimAmount = 0;
+}

Severity: Info
Confirmed by: Pashov (#8)

Description

If the interval is intended as a rate-limiter on yield captures, the Safe multisig can effectively bypass it by setting the interval to 1. This is a governance risk rather than a code bug, but a minimum interval (e.g., 1 hour) would provide a meaningful lower bound.

Discarded / Downgraded Items

  • Pashov #5 (Two-step partial-execution state): Under standard Gnosis Safe behavior, all state changes within a reverted EVM transaction are atomically rolled back. If _payRecipients fails, the strategy withdrawal is also reverted. The concern is only valid if a custom Safe guard absorbs the inner revert — a non-standard configuration. Downgraded to Lead.
  • Pashov #10 (Flash-loan MetaMorpho inflation grief): Attacker loses flash loan fees with no profit. Net-negative attack. Rejected.
  • Pashov #11 (Returndata bomb): MAMO_STRATEGY is immutable and trusted. Risk only materializes under compromise of that contract. Downgraded to Lead.
  • BPS math overflow: totalYield * bps — USDC total supply (~55B × 6 dec = 5.5e16) × 10,000 = 5.5e20, well within uint256. No issue.
  • getDistribution() uint16 downcast: BPS - sumBps ≤ 10,000 ≤ 65,535. Safe.
  • Reentrancy: nonReentrant is the first modifier. Standard Safe module execution does not create cross-contract reentrancy paths here.

Appendix: Core Invariant Analysis

The contract's safety invariant is:

getStrategyValue() + getSafeUSDC() >= protectedPrincipal

This invariant is checked explicitly (line 177) and is structurally guaranteed to hold in theory, but findings M-1 and M-2 demonstrate that integer rounding in ERC-4626 share math violates it in practice on any non-trivial withdrawal. Adding a small rounding tolerance (2 wei for USDC 6-decimal precision) is sufficient to fix both M-1 and M-2 simultaneously.

The protectedPrincipal serves as a high-watermark principal tracker. Its growth relies on the assumption that getStrategyValue() is consistent across calls within the same transaction — an assumption that ERC-4626's round-down semantics violates by construction when the strategy partially redeems its vault position.
