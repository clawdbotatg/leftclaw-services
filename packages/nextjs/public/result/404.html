Executive Summary

This is a well-defended codebase for a complex, 9-contract interlocking system — the core solvency invariant (deposits[agent] ≥ totalReserved[agent]), the dispute-bond reservation/consumption timing, the frozen-escrow snapshot-equality gate, and the USDC-token-pinning that neutralizes most of the reentrancy surface were independently stress-tested by upward of a dozen agents across two independent methodologies and held up in every case. The material findings instead cluster around the dispute-resolution game theory: the timeout path never forfeits the initiator's bond, escalate() can close the only non-consensual escape hatch, and a seated arbitrator is paid specifically for ruling against the initiator — together these let an unprivileged party extract value from a counterparty with no admin involvement at all, which is the most severe class of finding in this report. A second cluster covers module-replacement governance (the 2-day recovery timelock is bypassable by the owner via a faster rotate* path) and a redistribution quirk in the staking reward accumulator.

Findings: 2 High, 5 Medium, 7 Low, ~10 Informational/Leads.

Reconciliation summary: Overlap (both phases) · 4 · Phase-1-only · 8 · Phase-2-only · 6 · Re-examined leads kept · 5, demoted · 3 · Coverage holes closed this pass · 1 (settlement-digest domain-separator logic, examined for the first time in Turn 3 — confirmed a self-consistency commitment, not a signature scheme; invariant holds, no finding).

Findings

[H-01] Dispute-bond is never forfeited on timeout, and escalate() can force that timeout even with a fallback resolver configured — either party can freeze escrow and extract an unearned 50% split at zero net cost

Severity: High · Confidence: 95 · Origin: [phase2: 6 of 12 agents — economic-security, execution-trace, invariant, asymmetry, boundary, trust-gap]

Location: ArbitrationModule.escalate() (src/ArbitrationModule.sol:270-286), resolveTimedOut() (:292-301), _settleDisputeBond() (:442-467), assignFallbackResolver() (:321-337)

// ArbitrationModule.sol:270-286
function escalate(uint256 disputeId) external {
    Dispute storage d = disputes[disputeId];
    require(d.state == DisputeState.OPEN, "Arbitration: can only escalate OPEN disputes");
    require(block.timestamp <= d.resolutionDeadline, "Arbitration: selection closed");
    require(d.tier < MAX_TIERS, "Arbitration: max tier");
    require(
        msg.sender == d.snapshotPoster || msg.sender == d.snapshotWorker,
        "Arbitration: not party"
    );

    d.tier              += 1;
    d.proposedArbitrator = address(0);
    d.posterConsented    = false;
    d.workerConsented    = false;
    uint256 nextDeadline = block.timestamp + RESOLUTION_TIMEOUT;
    d.resolutionDeadline =
        nextDeadline < d.absoluteDeadline ? nextDeadline : d.absoluteDeadline;

    emit TierEscalated(disputeId, d.tier);
}

// ArbitrationModule.sol:292-301
function resolveTimedOut(uint256 disputeId) external {
    Dispute storage d = disputes[disputeId];

        d.state == DisputeState.OPEN || d.state == DisputeState.EVIDENCE,

// ArbitrationModule.sol:452-467 (comment is the developer's own stated intent)
/// @dev Bond settlement: refunded to the initiator's vault ledger when they prevail
///      or when no arbitrator adjudicated (timeout — nobody earned it); forfeited
///      to the arbitrator when the initiator's claim fails. Loser-pays funds the
///      arbitration market without a protocol-level arbitration fee.
function _settleDisputeBond(...) internal {
    uint256 bond = disputeBond[disputeId];
    if (bond == 0) return;
    disputeBond[disputeId] = 0;
    IERC20 usdc = IERC20(agentDepositVault.usdcToken());
    bool initiatorIsWorker = d.initiator == d.snapshotWorker;
    bool initiatorWon = initiatorIsWorker ? workerBps > 5000 : workerBps < 5000;
    if (byArbitrator && workerBps != 5000 && !initiatorWon) {
        _payBondOrDefer(usdc, d.assignedArbitrator, bond);   // forfeit branch — NEVER reached by timeout
        emit DisputeBondForfeited(disputeId, d.assignedArbitrator, bond);
    } else {
        usdc.forceApprove(address(agentDepositVault), bond);
        agentDepositVault.creditDisputeBond(d.initiator, bond);  // <-- timeout always lands here
        emit DisputeBondRefunded(disputeId, d.initiator, bond);
    }
}

Description: resolveTimedOut always calls _finalise(d, id, 5000, false) — byArbitrator=false unconditionally — so the forfeit branch's byArbitrator && ... condition can never be true on the timeout path; the initiator's bond is always refunded regardless of who "should have won." escalate() sets resolutionDeadline = min(now + RESOLUTION_TIMEOUT, absoluteDeadline); calling it repeatedly (once around day 7, once around day 14, tier-capped at MAX_TIERS) pins resolutionDeadline to absoluteDeadline, which zeroes out assignFallbackResolver's window (resolutionDeadline < now ≤ absoluteDeadline) — the neutral-fallback escape hatch closes even when fallbackResolver is correctly configured, not only when it's left unset.

Proof of Concept: Milestone task fully funded at $10,000; worker has proven nothing (or, symmetrically, has genuinely earned everything — the bug rewards whichever party opens the dispute). Initiator calls TaskRegistry.openDispute (permitted during ACTIVE/IN_REVIEW) → escrow freezes, a bond ($1–$100, clamped) is reserved+consumed from the initiator. Initiator never proposes an arbitrator the counterparty would also name (mutual consent required). At ~day 7 and ~day 14, initiator calls escalate() twice, closing the fallback window. After day 21, anyone calls resolveTimedOut → escrow.split(taskId, worker, poster, 5000) sends 50% ($5,000) to each party, and _settleDisputeBond refunds the initiator's bond in full. Net: the initiator extracts $5,000 they had no claim to, for ~3 transactions and 21 days, with their bond fully returned.

Recommendation: Forfeit the initiator's bond on timeout (byArbitrator=false) instead of refunding it. Cap escalate()'s effect so it can never close the assignFallbackResolver window to zero width (e.g. resolutionDeadline = min(now+RESOLUTION_TIMEOUT, absoluteDeadline - MIN_FALLBACK_WINDOW)). Consider requiring fallbackResolver != address(0) as a precondition for openDispute.

Description: For an ACTIVE task past its deadline with lockedBalance() > 0, expireTask unconditionally routes the entire remaining balance to the poster via refundRemainingToPoster, without checkpointing or carving out any already-vested (STREAMING) or already-accrued (HOUR_BLOCKS) worker pay that simply hasn't been pulled yet via claimStream/claimHourBlock. expireTask is permissionless — callable by the poster themselves.

Proof of Concept: STREAMING task, totalDeposited=100e6, linear vesting over a 10-day deadline. The worker, who fully earned this pay via elapsed time, receives $0. A poster can deliberately let the deadline pass (or race a claimStream transaction) to reclaim fully-earned wages for free. MILESTONE-mode tasks are unaffected (a submitted proof moves the task to IN_REVIEW, not covered by expireTask).

Recommendation: Before refunding in expireTask/refundRemainingToPoster for STREAMING/HOUR_BLOCKS tasks, checkpoint the stream/hours and release the vested-but-unclaimed portion to the worker first; only the genuinely-unearned remainder should return to the poster.

[M-01] Seated arbitrator is paid only for ruling against the dispute initiator — a standing incentive to rule against merit

Severity: Medium · Confidence: 85 · Origin: [phase2: economic-security (lead) → promoted via trust-gap (finding)]

Location: ArbitrationModule._settleDisputeBond() (src/ArbitrationModule.sol:442-467, quoted in H-01), consumed via resolveDispute() (:304-318)

Description: initiatorWon = initiatorIsWorker ? workerBps > 5000 : workerBps < 5000 — the bond is forfeited to d.assignedArbitrator exactly when byArbitrator && workerBps != 5000 && !initiatorWon. Since the arbitrator freely chooses workerBps in resolveDispute, they can pick a value 1 basis point away from 5000 in whichever direction makes initiatorWon=false, capturing the bond regardless of actual merits.

Proof of Concept: Worker-initiated dispute; arbitrator rules workerBps=4999 → initiatorWon=(4999>5000)=false → forfeit branch fires → arbitrator receives the bond. Symmetric for poster-initiated disputes at workerBps=5001. A rational initiator, anticipating this, should refuse to consent to any arbitrator at all — which directly feeds H-01's timeout exploit.

Recommendation: Decouple arbitrator compensation from ruling direction — pay a fixed fee from the bond regardless of outcome, or split it proportionally to workerBps.

Description: Disputes on escrow under $1 land in tier 0, which has no reputation clause at all — any address meeting the $25 entry-deposit minimum can be seated. Every resolveDispute call mints the same fixed reputation (+50) and resolvedCount (+1) regardless of the dispute's real stakes, and those are exactly the fields tiers 1/2 gate on.

Proof of Concept: Attacker controls addresses A (poster) and B (worker) — claimTask's only self-dealing guard is require(msg.sender != t.poster) (TaskRegistry.sol:254), which a second attacker-controlled address trivially satisfies. Attacker registers throwaway address C as a global arbitrator ($25 deposit). A posts+funds a $0.90 task, B claims it, A opens a dispute (_tierForAmount(0.9e6)=0). Both A and B call proposeArbitrator(id, C) — tier-0 skips the reputation check — C is seated, resolves, earns +50 rep / +1 resolvedCount. Repeated 5×: arbitratorReputation[C]=250 ≥ MIN_REP_TIER2(200) and resolvedCount[C]=5 ≥ MIN_RESOLUTIONS_TIER2(5) — C now satisfies every on-chain "tier-2 qualified" signal with zero legitimate history, and can subsequently be proposed for real high-value disputes where the forged reputation is precisely what would make honest parties trust it.

Recommendation: Apply a reputation floor to tier-0 resolution too (fold tier 0 into tier 1's gate), or require lockedAmount >= MIN_DISPUTE_BOND in openDispute so no dispute can be cheaper than its own bond floor.

[M-03] UnionStakingVault.stake() lets the first staker after any zero-total-stake interval capture the entire reward that streamed during that interval, regardless of stake size

Severity: Medium · Confidence: 85 · Origin: [both — phase1: precision-math+general (Low, Precision-1/General-3) → phase2: 7 of 12 agents, 2 independently reaching FINDING with numeric proof — severity revised up on reconciliation]

Location: UnionStakingVault.stake() (src/UnionStakingVault.sol:122-138), _updateRewardAcc() (:256-271), _checkpoint() (:348-352)

// UnionStakingVault.sol:122-138
function stake(uint256 amount) external {
    require(stakingActive, "UnionStaking: not active");
    require(amount > 0, "UnionStaking: zero amount");
    _accrue();
    _settle(msg.sender);

    uint256 beforeBalance = azlToken.balanceOf(address(this));
    azlToken.safeTransferFrom(msg.sender, address(this), amount);
    uint256 received = azlToken.balanceOf(address(this)) - beforeBalance;
    require(received > 0, "UnionStaking: zero received");
    stakers[msg.sender].staked += received;
    totalStaked += received;

    // If an old stream expired while stake was zero, allocate that carry
    // exactly once to this first resumed active-stake epoch.
    _checkpoint(msg.sender);      // <-- sets usdcDebt BEFORE the carry is folded in
    _updateRewardAcc();           // <-- folds undistributedRewardsScaled into accUsdcPerToken here
    emit Staked(msg.sender, received, totalStaked);
}

// UnionStakingVault.sol:256-271
function _updateRewardAcc() internal {
    uint256 streamEnd = block.timestamp < rewardPeriodFinish ? block.timestamp : rewardPeriodFinish;
    uint256 emittedScaled;
    if (streamEnd > lastRewardUpdateAt) {
        emittedScaled = (streamEnd - lastRewardUpdateAt) * rewardRateScaled;
        lastRewardUpdateAt = streamEnd;
    }
    if (totalStaked > 0) {
        uint256 distributableScaled = emittedScaled + undistributedRewardsScaled;
        if (distributableScaled > 0) {
            accUsdcPerToken += distributableScaled / totalStaked;
            undistributedRewardsScaled = 0;
        }
    } else if (emittedScaled > 0) {
        undistributedRewardsScaled += emittedScaled;
    }
}

Description: While totalStaked==0, streamed reward slices park in undistributedRewardsScaled. stake()'s trailing _checkpoint sets the new staker's usdcDebt to the pre-carry accUsdcPerToken, then the trailing _updateRewardAcc() divides the entire parked carry by the current (possibly dust) totalStaked and adds it to accUsdcPerToken — so the new staker's claimable reward is the full carry, independent of stake size or duration.

Proof of Concept: Staker A (100M AZL) stakes; a 7-day, $1,000 USDC stream starts. A fully unstakes at t=1s, totalStaked→0. Over the remaining ~7 days, ~$1,000 accrues into undistributedRewardsScaled. An attacker calls stake(1) (1 wei of AZL): the trailing _updateRewardAcc() computes accUsdcPerToken += ~1000e6*1e36 / 1, and since the attacker's usdcDebt was frozen one line earlier at the pre-carry value, claimableUsdc ≈ 1000e6 — the attacker claims essentially the entire stream for a 1-wei, zero-duration stake. This is not insolvency (claims never exceed what was genuinely streamed into the vault) but is a concrete, repeatedly-demonstrated redistribution away from future genuine stakers toward whoever re-stakes first after any full-unstake gap.

Recommendation: Release the zero-stake carry into the accumulator before checkpointing the new staker's debt (reorder: call _updateRewardAcc() before _checkpoint), or roll the carry into the ongoing rate over the remaining stream duration instead of lump-crediting the next entrant.

[M-04] ArbitrationModule.setFallbackResolver is the only re-settable wiring value — owner can redirect fallback-resolution authority mid-dispute

Severity: Medium · Confidence: 80 · Origin: [both — phase1: access-control P1-02 → phase2: 5 of 12 agents flagged as contributing lead (math-precision, access-control, economic-security, execution-trace, asymmetry)]

Location: ArbitrationModule.setFallbackResolver() (src/ArbitrationModule.sol:106-108)

// ArbitrationModule.sol:106-108
function setFallbackResolver(address _resolver) external onlyOwner {
    fallbackResolver = _resolver;
}

Description: Every other wiring value in the system is one-shot (address(0)-guarded, e.g. setReputationRegistry/setAgentDepositVault at lines 94-101). setFallbackResolver has neither a one-shot guard nor a zero-address check, and can be changed by the owner at any time — including mid-dispute, after assignFallbackResolver's window has opened. assignFallbackResolver's only eligibility check (ArbitrationModule.sol:331-334: agentDepositVault.meetsEntryMinimum(fallbackResolver)) means a seated fallback resolver also bypasses the reputation-tier gating that the consensual path enforces (see M-02's related tier-gap).

Note — distinct from H-01: this finding requires an owner to act maliciously (redirect the fallback resolver to a colluding address, then have it seated and rule unfairly); H-01 requires no privileged action at all (a party simply refuses consent and calls escalate). Both degrade the same subsystem via different actors and are reported separately.

Recommendation: Make setFallbackResolver one-shot or timelocked, and forbid changing it while any dispute is OPEN/EVIDENCE. Add a non-zero-address guard. Apply the same tier/reputation checks used in proposeArbitrator to the seated fallback resolver.

[M-05] Owner-gated rotate*Module/rotateArbitration provides an instant, un-timelocked path to the same end-state as the 2-day ArbitrationRecoveryCoordinator

Description: The four rotate* functions gate on exactly the preconditions the timelocked ArbitrationRecoveryCoordinator also requires (paused, zero active disputes, zero pending side-effects, wiring-consistency), but with no delay. The only precondition (pausing the module) is itself an unrestricted onlyOwner toggle the owner already controls. EscrowVault.split (confirmed above: the EscrowRecord struct does store e.poster/e.worker at lines 24-25, but split never cross-checks the caller-supplied worker/poster parameters against them) means a malicious replacement module could redirect funds to arbitrary addresses once wired in.

Reconciliation note: Phase 1's access-control domain rated this High, reasoning that it defeats the stated purpose of the 2-day timelock.
